## 一、规划目标与数据背景

### 1.1 核心目标

围绕**搜索曝光（Impressions）→ 搜索点击率（CTR）→ 站内工具点击与使用（Engagement）→ 社交分享回流（Referral / Direct）**四个环节，在不违背本站可信度红线（不伪造官方数据、不将 `TBD` 词条混入计算器）的前提下，完成 5 项高 ROI 功能与 SEO 升级。

### 1.2 现状数据瓶颈分析

基于 `docs/targets/04-收录监控与数据看板.md:336-352` 记录的 28 天 GSC 与 GA4 真实数据：

1. **内页有曝光但点击率极低，排名卡在 40–50 名**：
   - `/`：`42` clicks / `1,453` impressions（平均排名 `12.47`）
   - `/trading-values/`：`2` clicks / `387` impressions（平均排名 `43.89`）
   - `/rarity-list/`：`0` clicks / `222` impressions（平均排名 `49.58`）
   - `/calculator/`：`5` clicks / `173` impressions（平均排名 `43.54`）
   - `/tier-list/`：`1` click / `126` impressions（平均排名 `51.07`）
2. **大量具体 Brainrot 单品搜索词已进入前 20–80 名，但缺少独立详情页承接**：
   - GSC 已出现 `popcuru and fizuru value`（pos `6`）、`bumbatron value sab`（pos `15`）、`celularcini viciosini value`（pos `21`）、`los fruits value`（pos `37`）、`glorbo fruttodrillo rarity steal a brainrot`（pos `47`）、`capitano gullini value`（pos `52`）、`nacho spyder value`（pos `54`）、`las sis value`（pos `57.75`）等 16+ 个单品长尾词。
3. **站内跳转意愿强，但缺乏从词条到计算器的直接转化入口**：
   - GA4 中 `related_tool_clicked` 达 `52` 次，但 `calculator_add_item` 仅 `14` 次；用户在首页或 Tier List 看到已核验价格词条时，无法一键带入 `/calculator/` 比价。

### 1.3 五项改造的执行顺序与分工

按代码依赖关系分为三个阶段依次落地：

1. **阶段 A（数据层与核心工具升级）**：
   - 事项四：扩展 `BrainrotItem` 基础收益字段与 `M/s per $1` 计算辅助函数，在 `/calculator/` 与 `/tier-list/` 增加基础收益对比。
   - 事项二 & 事项三：实现 `/calculator/` URL 参数解析、预填与一键复制交易分享链接，并在首页、`/trading-values/`、`/tier-list/` 增加带参跳转入口。
2. **阶段 B（核心页面 SEO 与 Schema 增强）**：
   - 事项一：优化 `/`、`/trading-values/`、`/calculator/`、`/tier-list/`、`/rarity-list/` 的 `title` / `description`（覆盖 `SAB`、`Best Brainrots`、`Rarest` 高搜索量意图），并为包含真实 FAQ 的页面注入 `FAQPage` JSON-LD。
3. **阶段 C（单品详情页矩阵与 Sitemap 扩展）**：
   - 事项五：新增静态预渲染路由 `src/app/brainrots/[slug]/page.tsx`（52 个单品页），更新 `src/app/sitemap.ts` 与全站词条卡片内链。

## 三、事项二：列表页一键带参跳转 Calculator 比价

### 3.1 改造原因与代码现状

- 在 `src/components/ValueTable.tsx:332-358` 与 `src/app/trading-values/page.tsx:194-224` 中，已验证价格的 10 个词条目前仅展示外部链接（StarPets 与 Eldorado），没有提供把当前词条直接送入 `/calculator/` 的站内工具入口。
- 在 `src/components/TradeCalculator.tsx:108-109` 中，`mine` 和 `theirs` 初始恒为空数组 `[]`，不支持通过 URL 查询参数自动添加词条。

### 3.2 入口位置与跳转链接规范

1. **首页 `src/components/ValueTable.tsx`**：
   - 当 `isVerifiedTradeValue(item)` 为 `true` 时，在 `.source-links` 首部渲染站内跳转链接：
     - 跳转地址：`/calculator/?add=${item.slug}`
     - 按钮文案：`Compare in calculator`
     - 埋点属性：`data-analytics-event="related_tool_clicked"`、`data-analytics-label={item.slug}`、`data-analytics-location="value_table_compare"`
2. **Trading Values 页 `src/app/trading-values/page.tsx`**：
   - 当 `hasVerifiedValue` 为 `true` 时，在 `Source status` 列的 `.source-links` 首部同样渲染 `Compare in calculator` 链接（`data-analytics-location="trading_values_compare"`）。
3. **单品详情页 `src/app/brainrots/[slug]/page.tsx`**（事项五）：
   - 已核验词条首屏主按钮直接指向 `/calculator/?add=${item.slug}`。

### 3.3 Calculator URL 预填参数契约

`/calculator/` 页面支持通过 URL Query 参数预填单侧或双侧交易词条，输入与解析后状态契约如下：

```json
{
  // 入参：浏览器地址栏 window.location.search 查询参数
  "input": {
    "add": "ketupat-bros", // 可选，单个已核验词条的 slug，默认加入 mine（Your offer）且数量为 1
    "mine": "ketupat-bros:1,la-sahur-combinasion:2", // 可选，Your offer 词条列表，格式为 slug:quantity 逗号分隔
    "theirs": "rosey-and-teddy:1,globa-steppa:2" // 可选，Their offer 词条列表，格式为 slug:quantity 逗号分隔
  },
  // 出参：解析并校验（仅保留 isVerifiedTradeValue 为 true 的词条，数量限制在 1~99）后的组件状态
  "output": {
    "mine": [
      {
        "itemId": "ketupat-bros", // 已核验词条 ID
        "quantity": 1, // 合法化后的整数数量（1~99）
        "rawQuantity": "1" // 输入框受控显示文本
      }
    ],
    "theirs": [
      {
        "itemId": "rosey-and-teddy", // 对方报价已核验词条 ID
        "quantity": 1, // 合法化后的整数数量（1~99）
        "rawQuantity": "1" // 输入框受控显示文本
      }
    ],
    "mineSelection": "ketupat-bros", // Your offer 下拉框默认选中项
    "theirSelection": "rosey-and-teddy" // Their offer 下拉框默认选中项
  }
}
```

## 四、事项三：Calculator 交易单链接分享与文本复制

### 4.1 改造原因与代码现状

- 玩家使用交易计算器的高频需求是将配好的报价单发到 Discord 或聊天窗口证明交易公平性（W/F/L）。
- 当前 `src/components/TradeCalculator.tsx` 未将报价状态同步到 URL，也没有提供复制分享链接或复制报价摘要的操作按钮。

### 4.2 URL 双向同步与分享按钮交互

1. **URL 状态同步**：
   - 当用户在 `TradeCalculator.tsx` 中增删词条或修改数量时，使用 `window.history.replaceState` 将当前 `mine` 和 `theirs` 编码到 URL 查询参数 `?mine=...&theirs=...`（两侧均为空时恢复为 `/calculator/`），不触发页面重刷或新增多余历史栈。
2. **新增两个操作按钮**（位于计算器顶部结果栏下方或面板底部操作区）：
   - **`Copy trade link`**：复制带 `?mine=...&theirs=...` 参数的完整 URL 到剪贴板，按钮文案在 2 秒内短暂变为 `"Link copied!"`。
   - **`Copy summary`**：复制可读的纯文本对比摘要（包含两侧词条明细、总 USD、总 `M/s`、差价结论及站点链接），方便直接粘贴到 Discord 聊天框。
   - **`Clear both sides`**：当任一侧非空时显示，一键清空两侧报价。

### 4.3 分享与埋点事件数据契约

新增与扩展的 GA4 埋点事件入参格式如下：

```json
{
  // 事件 1：用户点击复制交易链接或复制文本摘要时触发
  "calculator_share_clicked": {
    "share_type": "link", // 分享类型："link"（复制链接）或 "summary"（复制文本摘要）
    "mine_count": 2, // Your offer 中的词条种类数
    "theirs_count": 1, // Their offer 中的词条种类数
    "verdict_label": "Near equal" // 当前比价结论标签
  },
  // 事件 2：用户通过带参 URL（?add= 或 ?mine=）进入计算器并成功预填词条时触发
  "calculator_prefill_loaded": {
    "prefill_source": "add_param", // 预填来源："add_param"（单品直跳）或 "shared_offer"（分享链接）
    "items_loaded": 1 // 成功预填的词条总数
  }
}
```

## 五、事项四：新增基础收益（M/s）与性价比（M/s per $1）对比维度

### 5.1 改造原因与代码现状

- 在 `src/lib/data.ts:49-160` 中，10 个已核验词条均已有精确的 `baseIncomeMps`（数值，单位 `M/s`）；而在 `src/lib/data.ts:233-449` 中，其余词条的基础收益（如 `170M/s`、`275K/s`、`$1.2K/s`）写在 `notes` 字符串中，未提取为结构化展示字段。
- 在交易与购买决策中，玩家除了看 USD 售价，还高度关注“每秒收益（`M/s`）”以及“每 1 美元能换多少 `M/s`（`M/s per $1`）”。

### 5.2 数据结构扩展规范

在 `src/lib/types.ts` 的 `BrainrotItem` 及 `src/lib/data.ts` 的辅助函数中扩展基础收益字段与计算返回结构：

```json
{
  // BrainrotItem 新增可选结构化展示字段
  "brainrotItemExtension": {
    "baseIncomeText": "145M/s", // 格式化后的 Default 基础收益文本（如 "145M/s"、"300K/s"、"Unknown"）
    "baseIncomeMps": 145 // 可用于数值计算的每秒百万收益（单位 M/s；仅对已确认数值的词条提供）
  },
  // 辅助函数 getOfferIncomeSummary(offer, itemsById) 的出参结构
  "offerIncomeSummaryOutput": {
    "totalMps": 192.5, // 当前报价单所有词条累加的每秒基础收益（单位 M/s，按小数点后一位归整）
    "formattedTotalMps": "192.5M/s", // 格式化后的总基础收益字符串
    "mpsPerDollar": 17.78, // 每 1 美元对应的 M/s 收益（totalMps / totalUsd，保留两位小数）
    "formattedMpsPerDollar": "17.8M/s per $1" // 格式化后的性价比文本
  }
}
```

### 5.3 页面展示位置与计算规则

1. **`/calculator/`（`src/components/TradeCalculator.tsx`）**：
   - 在每侧报价面板底部的 `Total` 行下方，新增一行 `Base income`：显示该侧总基础收益（如 `145M/s Default`）及性价比（如 `13.4M/s per $1`）。
   - 在每個报价行 `<div className="offer-row">` 的单价旁，同时显示单品基础收益：`$10.83 each · 145M/s`。
2. **`/tier-list/`（`src/components/TierBoard.tsx`）**：
   - 排序下拉框新增 `"value-efficiency"`（`Best M/s per $1`），支持按每美元获得的 `M/s` 收益从高到低排序。
   - 每张 Tier 卡片底部小字展示：`145M/s · 13.4M/s per $1`。
3. **首页 `<ValueTable />`（`src/components/ValueTable.tsx`）**：
   - 词条卡片右侧胶囊区若该词条存在 `baseIncomeText`，展示基础收益胶囊（如 `145M/s` 或 `300K/s`），让玩家一眼看到每个词条的产钱能力。
